# v0.4 governed real tasks

## Change policy

Every run evaluates the actual Git change set after Codex finishes and before any configured check, commit, push, or pull-request call.

- Always fail: `.env` and `.env.*` paths, PEM/key files, secret/credential/creds paths, `.git`, malformed or escaping paths, configured forbidden roots, and run-level forbidden roots.
- Sensitive: package manifests and lockfiles, `.github/workflows`, `scripts`, `vercel.json`, Dockerfiles, deploy/deployment roots, and a diff containing security or auth-related changes. These require an explicit approval before checks, commit, push, or PR creation.
- Budgets: each project sets `maxChangedFiles` and `maxDiffLines`; defaults are 8 and 500, while LeadFinder is 3 and 200. A breach fails as `change_budget_exceeded`.

Requested scope is a pair of optional arrays, `allowedPaths` and `forbiddenPaths`, supplied by repeated CLI flags. Values are literal repository-relative roots, not a custom task DSL. The worker receives the scope as a constraint, but the orchestrator verifies the actual diff independently.

## Preflight

Run `agent doctor --project leadfinder` before a governed real task. It emits project/repository/default branch, GitHub connectivity, Codex availability, managed workspace root, configured commands, Vercel configuration, `VERCEL_TOKEN` presence, and GitHub branch-protection evidence. It never prints a credential and has no write or deployment behavior.

## Human boundary

Approval is required for sensitive changes; normal in-scope changes can continue through the existing governed PR flow. Neither category can merge a PR or run a production deployment. Human review remains required for every PR.
